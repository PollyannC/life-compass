# 本地日记与可视化

默认资料库 `~/Desktop/Life coach/Journal/`；尊重用户另选位置。首次实际使用时创建所需目录。每轮收到用户实际内容后保存或更新进行中草稿及相应图形；探索、复盘结束或暂停时再核对和保存，优先延续同一进行中记录，避免同日多次覆盖。保存失败时如实报告，可继续对话并在可行时重试；提供可复制的未保存摘要和图形，恢复后仅在用户确认的目录写入。用户提供的原话和 AI 归纳、推断、假设、建议分开；只写用户实际分享的信息。标题不要泄露敏感细节，记录中注明日期、来源、状态和更正。删除或修改记录按用户意愿执行。

```text
Journal/
  首页.md                    # 当前方向、进行中条目、最近复盘的索引
  方向/人生罗盘.md           # vision、anti-vision、价值、身份、边界及版本
  日记/YYYY-MM-DD-主题.md    # 每次会话；重名加序号
  主题/主题名.md             # 多次出现的主题、来源和假设状态
  图形/YYYY-MM-DD-复盘.md    # 本次 Mermaid 图快照；每次保存
  图形/人生罗盘.canvas       # 可选维护的 Obsidian JSON Canvas 总览
```

每篇日记记录：用户原话与事实、感受、已发生的行动、愿景关联、推断/假设及不确定性、积极进展和未达成之处、用户选择的下一步、下次回看点及相关 `[[主题/主题名]]` 链接。尚未结束标为进行中；不得将未发生的行动记为完成。用户确认后的修改要保留原始语境及更正。

在对话展示与本次内容相匹配的简洁 Mermaid 图或图表，并把对应 Mermaid 源保存到本次 `图形/` 快照。节点标注用户提供、记录、推断、假设、情境等类别；假设连接使用虚线。没有数据时画方向结构并标“待探索”，不得伪造进度。解释图的局限：链接是关联而非因果证明。

Obsidian 的 Graph View 根据笔记内链接生成关系图；它不是一张预先生成的固定图片，也不验证因果。主题索引写入出处链接，AI 提出跨次关联时标“待确认”，不擅自将其当作已证实模式。需要自由布局时生成或更新有效的 JSON Canvas `.canvas` 文件：包含 `nodes` 和 `edges` 数组，使用指向实际 Markdown 文件的 file 节点及稳定不重复的 id；保留已有用户手工布局和节点，不覆盖无关内容。无法安全合并时保留旧文件并新建候选画布。

本地记录通常是明文，实际隐私受设备、备份和已有云同步设置影响；不要承诺自动加密或本机专属处理。不要未经授权将个人记录、画布或摘要推送至 GitHub、邮件或其他服务。仅分享 skill 本身时排除整个 Journal 目录。
